# ADR-0001：WebSocket 长连接与 HTTP 短连接物理隔离

## 状态

accepted（追溯记录：决策实际发生于项目初期，本文为记忆库建立时的补录）

## 背景

客服系统的核心负载是海量并发 WebSocket 长连接 + 实时消息收发。若长连接与普通 HTTP API 共用 Spring Cloud Gateway，高并发长连接会耗尽网关线程/内存，拖垮所有普通接口路由。

## 决策

设立独立的 `chat-server` 微服务专职维护 WebSocket 长连接，前端 `ws://` 流量**绕过主网关直连该服务的独立端口**。HTTP 流量仍统一走 `api-gateway`。

鉴权方式：JWT 放在 WS URL 的 Query 参数中（浏览器原生 WebSocket 不支持自定义 Header），由 `chat-server` 的 `JwtWebSocketInterceptor` 在握手阶段校验。

## 后果

- ✅ 长短连接故障域隔离，长连接洪峰不影响 HTTP 路由。
- ✅ `chat-server` 可独立水平扩容。
- ⚠️ 前端需维护两个入口地址（网关 + WS 端口）；部署时需额外暴露端口。
- ⚠️ JWT 出现在 URL 中，需注意日志脱敏。
