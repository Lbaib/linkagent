# 客服业务域

> 智能客服的业务概念模型。随功能演进持续补充。

## 核心实体

- **访客（Visitor）**：无账号用户，以匿名 JWT 标识；发起会话的主体。
- **会话（Session/Conversation）**：一次完整服务过程，状态机：`AI 托管 → 人工排队 → 人工服务 → 已结束（评价/工单归档）`。
- **消息（ChatMessage）**：会话内的最小通信单元，先入 Redis 后异步落库。
- **坐席（SysUser/Agent）**：人工客服，有在线状态与接待量上限（默认 5）。
- **知识库文档**：上传 → 解析 → 切片 → 向量化（1536 维）→ pgvector 存储。
- **工单**：全员离线时的留言载体；会话结束后的归档记录。

## 关键业务规则

1. **转人工双轨制**：用户主动点击，或 AI 置信度低/检测到情绪波动时被动触发。
2. **分配算法**：过滤满载坐席 → 剩余坐席轮询（Round-Robin）；无可用则 Redis 排队并实时推送位次；全员离线转留言。
3. **单客服接管（现行演示）**：同一访客在已绑定坐席后，重复「转人工」不得再分配给其他坐席（幂等）；客服消息须带 `visitorId` 且校验绑定。详见 [[demo-closed-loop-invariants]]。
4. **上下文漫游**：坐席接单即拉取该访客全部历史（含 AI 对话），客户无需复述。
5. **满意度闭环**：会话结束推送评价卡片，归档为服务工单。
6. **凭证隔离**：访客匿名 JWT 存 `sessionStorage`；坐席登录 JWT 存 `localStorage`——不得混用。
